# PCR 轴表 ↔ 分享码

## Overview

把会战轴编码成 MaaPcrclanbattle 可导入的分享码，或把分享码还原成可读轴表。
支持两种码，用分隔符一眼可辨：

- **开关SET**：`轴名:base62码!延时表`（`:` 分隔）
- **单次UB**：`轴名#指令串#五个角色名`（`#` 分隔）

核心思路是**职责分离**：看图和抽取字段交给模型，编码和校验交给脚本。
脚本在输出前会做语法/往返自检，不一致就直接报错退出，**不会产出错误的码**。

## 和本仓库的关系

本 skill 随 MaaPcrclanbattle 仓库一起分发：
仓库里在 `.workbuddy/skills/pcr-timeline-to-sharecode/`，
Release 包里在解压目录的 `.workbuddy/skills/pcr-timeline-to-sharecode/`（由 `install.py` 复制）。
它只负责「轴 ↔ 分享码」这一步，不依赖仓库代码，可以脱离仓库单独使用。

编码规则与仓库的 `sharecode.py` / `pipeline.py` 完全一致。
如果还需要**生成能被 MFAWPF 直接执行的脚本**（写 `resource/pipeline/*.json` 并注册到
`interface.json`），用仓库的 `generator.exe` 命令行接口，见仓库 README 的「命令行接口」一节。

## 什么时候用

- 用户发来一张轴图 / 轴表截图，要分享码（SET 或单UB）
- 用户给了一个分享码，想知道它是什么轴（核对、排错）
- 用户想把手写轴录入 MaaPcrclanbattle

## 判断轴的类型

| 轴图特征 | 类型 |
|---|---|
| 有「状态」「开关」列，`oxooo` 这类串，每行一个时间 | 开关SET |
| 操作列是「角色名 / 连招 / AUTO / BOSS UB」的流水账，无开关列 | 单次UB |
| 用户直接给了码 | 看 `:` 还是 `#` 分隔 |

## 工作流

### Step 1 — 拿到轴的内容

按优先级：

1. **当前模型支持读图**：直接看轴图，抽取字段（SET 见 `references/axis-format.md` 第一部分，
   单UB 见第二部分）。
2. **不支持读图 / 图看不清**：明确告诉用户「我读不了这张图」，请他把轴表
   以文字粘贴出来，或按行口述。**不要凭猜测编造字段。**
3. 用户给的是表格 / 文本：直接进入 Step 2。

### Step 2A — 开关SET：抽成简写文本

```
# name: D3 37546W
# party: 生菜 水猪妹 若菜 水猫妹 诗夏
124 -        oxooo  -
109 生菜     oooox  -
057 生菜     xxxoo  A
```

列含义：`时间  触发角色  五人状态  [A=开auto]  [延时秒]`。开局行时间固定写 `124`。

### Step 2B — 单次UB：抽成操作流水

```
# name: d4 【三压】37000 一倍速
# party: 水狐 鹿妹 圣莱 火机 琳德
1:14 卡帧
水狐
火机AUTO
圣莱
0:58 -
```

**关键**：时间行只在「段落起点」写，不是每行都写——指令串里的 `s` 只出现在
作者重新校准倒计时的位置，连续操作挂在同一次等待后。其余规则见
`references/axis-format.md` 第二部分。

### Step 3 — 跑脚本

```bash
python scripts/axis_to_share.py --text axis.txt      # 开关SET
python scripts/axis_to_share.py --ub-text axis.txt   # 单次UB
python scripts/axis_to_share.py --decode "码"         # 反解（自动识别两种码）
```

### Step 4 — 交付前核对

**必须**把脚本打印出的可读序列和原始轴图逐行对一遍：

- SET：行数、每行 `o/x`、auto 落点、延时挂在正确的行（行号从 0 起）
- 单UB：把反解出的 42 条人话指令按顺序和图上操作列对——
  **图 → 码只保证操作序列和段落结构正确**；`s` 等待的落点和秒数属于作者
  人工微调（真实样本：图上 1:13 码里 s114；图上没有 0:58 行码里有 s058），
  如与用户意图不符，让用户改文本重新生成

核对无误再把码交给用户，并说明可以粘进 MaaPcrclanbattle 的分享码框直接还原。

## 硬性约束

- SET 时间在 `001-059` / `100-130`，`124` 是开局专用值；单UB 时间为 `M:SS`
- 触发角色必须能在 `# party:` 里找到，否则脚本报错
- SET 五人状态串必须恰好 5 位（auto 由 `A` 列单独给）
- 延时只认图上**明示的秒数**；只给帧数时按 `帧数/60` 换算后**必须向用户确认**
  （真实轴里 33 帧对应 0.1 秒，机械换算会错）
- 单UB 的 auto 语义是「开→等自动UB→自动关」三连，和 SET 的勾选框不是一回事

## 常见坑

- **SET 开局行别漏**（时间 124），漏了整条轴错位。
- **SET 只切 auto 的行不能合并**，连续两行状态相同只差 auto，必须各占一行。
- **SET「普攻后」时点填 0**，不填角色号位。
- **单UB 不要给每行标时间**，会生成一串多余的 `s` 把节奏打乱。
- **单UB 括号备注全部忽略**：`(41)`、`(炼冰开后，容错161帧)` 是给玩家看的，
  GUI 录入时会被正则删掉。
- **「克\*2」这种带星号的写法 = 连点两次**（`克*2` → `22`），别漏成一次；
  而 `克(53)` 里的数字是伤害标注，要忽略。
- **一行塞多个时刻的操作要拆行**（如 `1:21 克(AUTO) - 瓜智(115 AUTO)` 拆成
  `1:21 克AUTO` 和 `1:15 瓜智AUTO`）。
- **SET 的时点 = 触发角色在 `# party:` 里的号位**，所以必须先确认队伍顺序；
  轴图**标题里的角色顺序不等于号位顺序**（实测有标题与队伍顺序完全相反的例子）。
- **「押/唱名/目押/速压破甲」类字眼 = `k`（卡帧目押）**，这是它们在码里的唯一形态。
- **行号/下标从 0 起**。
