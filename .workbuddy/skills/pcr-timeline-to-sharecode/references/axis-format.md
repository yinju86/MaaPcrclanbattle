# 轴图字段 → 分享码字段 映射

分享码有两种：**开关SET**（`轴名:码!延时表`）和**单次UB**（`轴名#指令串#五个角色名`）。
两者编码完全独立，用 `:` 还是 `#` 分隔一眼可辨。

---

# 第一部分：开关SET

## 编码布局

每行轴 → 一个 6 位十进制数 → base62 **定长 3 字符**，所有行首尾相接，
末尾用 `!` 接延时表。

```
[ 时间 3位 ][ 时点 1位 ][ 6 个开关 → int(二进制,2) → 压成 2 位十进制 0..63 ]
   "049"        "3"         1,2,3,4,5 号位 + A(auto)，第 1 号位是最高位
────────────────────────────────────────────────────────────────
  拼成 "049363" → int() → base62 → zfill(3) → "1xZ"

全轴 = "1xZ" + "0kA" + ... + "!" + "9-0.1,3-2"
                                    ↑ 行号-延时，逗号连接，行号从 0 起
```

## 逐字段映射

| 轴图上的信息 | 编码字段 | 取值 | 说明 |
|---|---|---|---|
| 行首时间（如 `109`） | 时间 3 位 | `001-059`、`100-130` | 3 位数字原样填；`109` = 1 分 09 秒 |
| 「开局 / 初始状态」 | 时间 3 位 | 固定 `124` | 工具内部用 124 代表初始状态，**这一行不能漏** |
| 行首角色（如「109 **生菜**」） | 时点 1 位 | `0-6` | 该角色在队伍里的号位（1-5） |
| 「普攻后」「无 UB」 | 时点 1 位 | `0` | 不是任何 UB 后 |
| 「卡帧」 | 时点 1 位 | `6` | |
| `oxooo` / `oooox` 这类串 | 状态前 5 位 | 5 个 bool | `o`=开 `x`=关，从左到右是 1→5 号位 |
| 「开 auto」「关 auto」文字 | 状态第 6 位 | 1 个 bool | 独立于五人状态串 |
| 「延时 0.1」「容错 xx 帧」 | 延时表 | 秒（float） | 挂在**该行下标**上，下标从 0 起 |

### 关于时点的关键结论

轴图上每行标注的角色（生菜 / 水猪妹 / …）就是「这一刻是谁的 UB 之后」，
映射到编码的「时点」字段 = 该角色在队伍中的号位。

实测样本（D3 轴，队伍顺序 生菜 | 水猪妹 | 若菜 | 水猫妹 | 诗夏）：

| 图上标注 | 号位 | 解码出的时点 |
|---|---|---|
| 109 生菜 | 1 | 1 ✓ |
| 041 若菜 | 3 | 3 ✓ |
| 020 水猪妹 | 2 | 2 ✓ |
| 014 诗夏 | 5 | 5 ✓ |
| 003 水猪妹**普攻后** | — | **0**（不是 2）✓ |

最后一行是唯一的例外，也是最容易搞错的地方：**「普攻后」填 0，不填号位。**

## 队伍顺序从哪来

轴图顶部通常有一行角色头像/名字（如 `生菜 | 水猪妹 | 若菜 | 水猫妹 | 诗夏`），
从左到右就是 1→5 号位。填 `# party:` 时必须严格按图上的顺序。

如果图上没给队伍顺序，必须问用户，不能猜。

## JSON 输入格式

简写文本表达不了时（需要 UB 偏移、显式指定时点）用 JSON：

```json
{
  "name": "D3 37546W",
  "party": ["生菜", "水猪妹", "若菜", "水猫妹", "诗夏"],
  "rows": [
    {"initial": true,  "state": "oxooo", "auto": false},
    {"time": "109", "trigger": "生菜", "state": "oooox"},
    {"time": "057", "trigger": "生菜", "state": "xxxoo", "auto": true},
    {"time": "003", "stuck": true, "state": "xxooo", "auto": true, "delay": 0.1},
    {"time": "041", "time_point": 3, "state": "oxxoo"}
  ]
}
```

字段说明：
- `initial: true` → 时间自动填 `124`，不用写 `time`
- `trigger` → 角色名，自动查 `party` 得号位
- `time_point` → 直接指定时点，优先于 `trigger`
- `stuck: true` → 卡帧（时点 6）
- `state` → 5 位串，支持 `o/x`、`O/X`、`开/关`、空格分隔
- `auto` → 第 6 位
- `delay` → 秒，会写进延时表

## 轴名

`轴名:码`，例如 `D3 37546W:wgKso...`。轴名一般取自图上的 boss 编号和伤害
（`D3` + `37546W` = 37546 万）。

若轴带 UB 偏移，轴名前会拼 5 位数字（如 `12345轴名`），解码时前 5 位是纯数字才当偏移。
轴图里没有明示偏移就不要加。

## 完整真机样本

输入（`--text`）：

```
# name: D3 37546W
# party: 生菜 水猪妹 若菜 水猫妹 诗夏
124 -        oxooo  -
109 生菜     oooox  -
057 生菜     xxxoo  A
041 若菜     oxxoo  -
031 生菜     xoxoo  -
020 水猪妹   xoxoo  A
019 若菜     xoxoo  -
014 诗夏     oxooo  -
006 若菜     xxooo  -
003 -        xxooo  A  0.1
003 生菜     xoooo  A
```

输出：`D3 37546W:wgKsoEeR5aKK85Y5gb51E3MC1DQ0MD0Ov!9-0.1`
（与作者原始分享码逐字符一致，可作为回归样本）

## 回归样本二：D4 34067W（时点必须靠队伍号位才能推出来）

轴图 TL 区（队伍 `水狐 鹿妹 圣莱 火机 琳德`）：

| 时间 | 触发 | 状态 | auto |
|---|---|---|---|
| 开局 | — | `xOOXX` | 开 |
| 1:11 | 圣莱 | `XOXOX` | 关 |
| 1:01 | 鹿妹 | `OOXOO` | |
| 56 | BOSS | `XXXOO` | 开 |
| 44 | 圣莱 | `OXOOO` | 关 |
| 41 | 火机 | `OOOOO` | |

输入（`--text`）：

```
# name: D4 34067W
# party: 水狐 鹿妹 圣莱 火机 琳德
124 -      xOOXX  A
111 圣莱   XOXOX
101 鹿妹   OOXOO
056 -      XXXOO  A
044 圣莱   OXOOO
041 火机   OOOOO
```

输出：`D4 34067W:wgpsXuql8ezlbxgaMK!`（与作者原始码**逐字符一致**）

两点值得注意：

- **状态串直接用图上的 `O/X`**（大写同样被识别，`O`=开），
  **顺序就是编码里 1→5 号位的顺序**，不用按头像重新排列。
- **「56 BOSS」这行的时点是 0**（BOSS UB 无角色触发），
  和「普攻后」一样填 0。
- 时点完全由「触发角色在 `# party:` 里的号位」决定：`圣莱→3`、`鹿妹→2`、`火机→4`。
  **队伍顺序错了整条轴的时点就全错**——本例的队伍顺序恰好与
  轴图标题「琳德火机圣莱鹿妹水狐」相反，说明**不能拿标题顺序当号位**，
  必须确认工具里录入的队伍顺序。


## 数值上限

6 位十进制 → base62 三字符，上限 `62³-1 = 238327`。
当前业务域最大值是 `130` + `6` + `63` = 130663，余量约 1.8 倍。
一旦时间上限超过约 238，定宽假设失效，脚本自检会报错拦下。

# 第二部分：单次UB

## 码的形状

```
轴名 # 指令串 # 角色名1 角色名2 角色名3 角色名4 角色名5
```

真实样本：
`d4 【三压】37000 一倍速#s114k1a4345311s058a2s05641a3k243k142511a3s0274542a131a452311#1 2 3 4 5`

- 第三段是 5 个角色名（空格分隔），运行时用于提示「点击谁」。原作者可能用
  `1 2 3 4 5` 占位，**生成时推荐填真实角色名**，提示更友好，两者工具都接受。
- 轴名前 5 位若全为数字会被当作 UB 偏移（如 `12345轴名`）。
- 识别速度（一倍速/二倍速）**不进码**，是 GUI 菜单里的运行时设置。

## 指令串语法（权威格式，与 pipeline.py 解析状态机一致）

| 指令 | 含义 |
|---|---|
| `1`~`5` | 点击该号位角色的 UB，等它放完 |
| `aN` | 开 auto 等 N 号位自动 UB，结束后自动关 auto |
| `dN` | 延时 N 秒 |
| `sMSS` | 等倒计时走到 M:SS（s + 1 位分 + 2 位秒，如 `s114` = 1:14）|
| `k` | 卡帧，人工目押 |
| `\` `/` | 忽略 |

把样本逐 token 翻译（队伍 水狐|鹿妹|圣莱|火机|琳德）：

```
s114 k 1 a4 3 4 5 3 1 1 s058 a2 s056 4 1 a3 k 2 4 3 k 1 4 2 5 1 1
a3 s027 4 5 4 2 a1 3 1 a4 5 2 3 1 1
```

## 轴图 → 指令串 映射规则

| 轴图上的信息 | 指令 |
|---|---|
| 行首时间（多数行） | **通常不生成任何东西**，见下方「时间列真相」 |
| 需要重新校准倒计时的段落起点 | `sMSS` |
| 「BOSS UB」行 | 无操作（玩家只是等）；若该行是段落起点则给 `sMSS` |
| 普通角色名 | 号位数字 |
| 「**克\*2**」「**N\*2**」 | 该角色**连点两次**，生成 `号位号位`（如 `22`）|
| 「XX AUTO」 | `a号位` |
| 「押跳秒」「慢押XX唱名」「押XX唱名」「速压破甲」 | `k`（这类字眼就是「卡帧目押」的图面表达）|
| 括号里的纯数字 `(41)` `(53)` `(48)` | 伤害/计数标注，**忽略** |
| 括号里的动作说明 `(炼冰开后，容错161帧)` | **忽略**（GUI 录入时会被正则删掉）|
| 一行里塞了多个时刻的操作（如 `1:21 克(AUTO) - 瓜智(115 AUTO)`）| **拆成两行**，`(115)` 是 1:15 的简写 |
| 人工补的等待 | `s` 或 `dN` |

### 时间列真相（最重要的认知）

轴图上的时间列**只是给人看的参考**。指令串里的 `s` 只出现在作者需要
重新校准倒计时的位置，同一时段内的连续点击全部挂在一次等待之后：
`1:13` 到 `0:59` 的 6 行操作，在码里只有开头一个 `s114`。

**所以做文本时不要给每行都标时间**——标了就会生成一串多余的 `s`，
节奏完全走样。只在「段落起点」标时间。

### 人工微调无法从图上还原（明确接受不完美）

实测样本里有两处：
1. `s058`（等 0:58）在图上没有对应行——是作者在「0:57 鹿妹AUTO」前
   手工插的校准等待；
2. `s114` 对应图上写的是 1:13——押跳秒场景差 1 秒。

结论：**图 → 码只保证操作序列和段落结构正确，`s` 的落点和具体秒数
属于作者手感**。生成后必须把反解出的人话序列给用户核对，由他调整。

## 回归样本二：火410（含 `克*2`、`AUTO` 与 BOSS UB 行）

轴图（队伍 `火电 | 克 | 瓜智 | 星猫 | 黑骑`，秒数列 1:21→0:05，蓝底行是 BOSS UB）：

```
1:21  克(AUTO) - 瓜智(115 AUTO)      1:02  火电 - 瓜智 - 克 - 瓜智(56)      0:32  火电 - 黑骑 - 瓜智 - 克(30)

                    ↑ 0:39 那行是「瓜智 - 星猫(38) - 克*2(38-37)」
```

产出：`火410#s121a2s115a32s108k4s10513234a225a3134221532a432135243213425#火电 克 瓜智 星猫 黑骑`

作者原码：`火410#s122a2s117a32s110k4s10413234a225a3134221532a432135243213425#火电 克 瓜智 星猫 黑骑`

**逐字符比对结果**：59 个字符里只有 **4 个 `s` 的秒数不同**
（我 `121/115/108/105`，作者 `122/117/110/104`，差 +1/+2/+2/−1），
`k4` 之后 **38 条指令完全相同**。把 4 个 `s` 换成作者取值即字节级一致。

### 由此得出 `s` 的取值规律

`s` 是「原地等倒计时到某秒」，一般取在**动作前一秒左右**给点击留提前量，
所以 `s` 值往往比图上那一行的时间**早 1~2 秒**；段落起点落在 BOSS UB 行时
则可能取值反而**晚于**该行时间（`1:05 BOSS UB` → `s104`）。这属于作者手感，
**不要试图从图上精确还原**，生成后交给用户微调即可。

注意 `克(53 AUTO)` 里的 `53`、`星猫(38)` 里的 `38` 都是伤害标注，与
`克*2(38-37)` 这种「连点次数」写法完全不同，别把数字当次数。
